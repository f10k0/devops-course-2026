# Сравнение Git и SVN

## 1. Почему в Git ветвление "дешёвое", а в SVN - "дорогое"?
Я думаю, что дело в архитектуре. В Git ветка - это просто метка на коммит, она занимает мало места и создаётся почти мгновенно. В SVN же, чтобы создать ветку, система копирует все файлы проекта в отдельную папку, что отнимает много времени и дискового пространства. Поэтому ветвление в SVN - более тяжёлая операция.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет, потому что SVN - централизованная система. Все данные хранятся на сервере, и коммит - это отправка изменений на этот сервер. Без подключения к сети вы не можете передать изменения, а значит, и коммит сделать нельзя. Можно только изменять локальные файлы.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
Мне кажется, SVN всё ещё используют в организациях с жёсткими правилами безопасности, где нужен строгий контроль доступа к репозиторию. Также он остаётся в старых проектах, где уже всё настроено под SVN и переходить на Git слишком дорого. Иногда SVN выбирают для команд, которым проще работать с одной центральной веткой без сложных ветвлений.
